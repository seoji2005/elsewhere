# C109 도렌 수정: 공정한 경쟁·정보 경계·정산 (Claude 클라우드 opus)
목적: Codex 교차 리뷰(docs/design/REVIEW-c099.md) P1 3건·P2 3건을 고친다. 통합된 main(rival 시스템 포함)에서 출발.
1) 구매 의도 중복: 도렌이 별도로 매시간 구매를 추첨하지 말고, 기존 수요 슬롯의 공통 의도 ID로 '어느 가게에서 살지'를 고르고 결제 점포를 고정(한 의도 = 한 결제, 시간이 달라도).
2) 도렌만 제약 우회: 두 점포에 같은 후보 자격·주차(patrons 주차 규칙)·applyPersona·가격 허용치 검사. maxPrice를 판매가로 쓰지 않는다.
3) 정보 경계: 도렌은 공개 진열·실제 대기열·현장 관측(도렌 또는 직원이 그 시각 그 장소에 있을 때, ctx.placeOf)만 사용. 플레이어 창고 재고·실시간 판매 이력은 못 본다.
4) 발주·광고 예산: 체불·세금·고정비를 뺀 공통 가용액에서 순차 차감.
5) 폐점 정산: 마지막 영업일 임대료·과세 매출 처리 → 채무 보존 → 재고·고용·임대 종료.
6) 품절 소문: 원본 방문 ID·품목·시각을 저장해 그대로 전달.
7) (통합 세션 보고, 최우선) 도렌이 도시의 돈을 빨아들임: 180일 뒤 도렌 현금 3,401결, 주민 57명 합계 620결·31명 빈털터리, 플레이어 180일 매출 76,042→25,715결. 도렌의 돈이 다시 도는 길을 만든다 — 직원 고용(주민 임금), 주민 생산자에게서 매입(기존 supplyDay처럼), 도렌 개인 소비, 이익 상한 넘으면 확장 투자(이웃에게 임대료·인테리어 대금). 새 돈 생성 금지. 180일 주민 지갑 분포(중앙값·빈털터리 수)와 플레이어 매출을 도렌 합침 전과 비교하는 표·테스트(빈털터리 주민 ≤ 도렌 전 수준 + 3명).
