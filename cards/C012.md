# C012 폰 성능: 선명함을 지키면서 60fps (Claude 작업자)

목적: M1-04. 사용자 폰 실측: 돌아다니면 40fps, 해상도 약 500p(자동 조절이 바닥까지 내림). C007 전에는 1.25배 해상도에서 60fps였다.
사용자는 흐릿함(360~480p)을 싫어한다 → 해상도는 마지막에 낮추고, 효과를 먼저 줄인다.
목표: 사용자 폰(아이폰 계열, 3배 밀도 가정)에서 렌더 높이 780p 이상(기기 배율 2 이상), 걸어 다닐 때 55~60fps.
고칠 파일:
- src/main.ts, src/render/*.ts, src/scene/*.ts
- src/ui/debug.ts (새 파일)
크기: 큼(≤400줄)
하지 말 것: 걷기 조작·UI 동작 변경, 장면 내용 삭제(같은 모습 유지), 새 패키지, 커밋
통과 기준:
1. 측정 도구: `?debug=1`이면 화면 구석에 fps·렌더 높이(px)·그리기 호출 수·삼각형 수. URL로 기능별 끄기/바꾸기: `msaa=0|4`, `bloom=0|1`, `lut=0|1`, `shadow=off|static|dynamic`, `dpr=숫자(고정)`. 사용자가 링크 몇 개로 어떤 게 비싼지 잴 수 있게.
2. 기본값을 모바일 모범 사례로:
   - 고정밀 렌더 대상 MSAA 4배 끄기(필요하면 마지막 합성 패스에 값싼 FXAA). 높은 해상도가 계단을 줄인다.
   - 그림자: PCFSoft → PCF, 정적 장면 그림자는 한 번만 그리기(해·장면이 바뀔 때만 갱신). 움직이는 캐릭터·차는 접촉 그늘로.
   - 정적 건물·소품을 재질별로 합치거나 인스턴싱해서 그리기 호출 ≤ 200 목표.
   - 블룸·LUT를 가능한 한 패스로 합치고 블룸은 1/4 해상도.
3. 자동 품질 단계: fps가 부족하면 블룸 해상도 → 블룸 끄기 → 그림자 해상도 → 마지막에 해상도(바닥: 기기 배율 1.6). 올릴 때는 반대 순서.
4. 이전/이후를 같은 카메라로 찍어 모습이 거의 같아야 한다(직접 보고 비교). 서버에서 잰 그리기 호출·삼각형 수를 보고에.
5. `bash tools/check.sh --card cards/C012.md` PASS.
