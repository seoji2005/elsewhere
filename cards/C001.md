# C001 프로젝트 뼈대와 자동 검사

목적: 이후 모든 카드가 쓸 빈 프로젝트와 자동 검사 `tools/check.sh` (기능 목록 밖 기반 작업)
고칠 파일:
- index.html, vite.config.ts, tsconfig.json
- src/main.ts
- tools/check.sh, tools/scope-check.mjs, tools/shot.mjs
- package.json (scripts 칸만)
크기: 큼(≤400줄) — 새 프로젝트라서
하지 말 것: 게임 기능(건물·NPC·UI), 새 패키지 설치(이미 설치됨: three, vite, typescript, vite-plugin-singlefile, playwright, vitest, gltf-transform), 커밋, 다른 파일 수정
통과 기준:
1. `npm run build:single` → `dist-single/index.html` 한 파일. 방식은 /home/dev/citylight/vite.config.ts를 참고(읽기만).
2. src/main.ts는 폰 가로 화면을 채우는 빈 3D 장면(하늘색 배경, 바닥 평면, 카메라)만. 그 이상 없음.
3. tools/shot.mjs: /home/dev/citylight/tools/shot.mjs를 참고해 폰 가로(852×393) 스크린샷 → `.shots/*.jpg`, `.shots/sheet.html`. 콘솔 오류가 있으면 실패.
4. tools/check.sh [--fast] [--card cards/Cxxx.md]: 순서대로
   타입 검사 → `tests/`에 테스트가 있으면 vitest → build:single → 용량 10240KB 이하 → (--fast가 아니면) 스모크 스크린샷
   → (--card가 있으면) tools/scope-check.mjs 실행. 하나라도 실패하면 exit 1, 마지막 줄에 PASS/FAIL.
5. tools/scope-check.mjs <카드>: 카드의 "고칠 파일:" 목록(줄마다 쉼표로 여러 개, `*` 글롭 허용)과 실제 변경을 비교.
   변경 = `git diff --name-only HEAD` + 추적 안 되는 새 파일(.gitignore 제외). `cards/`, `progress.md`, `package-lock.json`은 무시.
   목록 밖 파일이 있으면 실패. 변경 줄 수(추가+삭제, 새 파일은 전체 줄)가 "크기:"의 등급(작음 40, 보통 150, 큼 400)을 넘으면 실패. 결과를 한 줄씩 출력.
6. Codex 샌드박스 안에서는 `bash tools/check.sh --fast --card cards/C001.md`가 PASS여야 한다(스크린샷은 마스터가 밖에서 돌린다).
