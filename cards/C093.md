# C093 타이쿤 시스템 등록부 + 세이브 v6 + 틱 연결 (Claude 클라우드 opus)
목적: docs/design/GDD.md §3. 새 타이쿤 기능(손님 의도·운반·직원·광고·라이벌·사건·전문가·기회·AI 외주·공연)을 각자 '시스템 파일 하나'로 만들어 병렬 개발할 수 있게 하는 그릇. 이후 카드는 session.ts 대신 자기 시스템 파일과 등록부 한 줄만 고친다.
고칠 파일:
- src/game/tycoon/system.ts, (새: 타입) — `TycoonSystem<S>`: `id`, `create(ctx): S`, `validate(raw: unknown, ctx): S`(잘못되면 throw), 선택 `onMinute(ctx, s, minute)`, 선택 `onDay(ctx, s, day)`(하루 마감 23:59 뒤 한 번). `TycoonCtx`: world(ledger·clock·people), book, leases, purses, residents(읽기), npcSeed, player, time(GameTime), roll(system, entity, index) 바로가기(tycoonCore.roll + npcSeed), settle/nextId 바로가기, `systems`(다른 시스템 상태 읽기 — 읽기만).
- src/game/tycoon/registry.ts, (새) — `export const tycoonSystems: TycoonSystem<any>[] = []` (지금은 비어 있음. 이후 카드가 import + 배열에 한 줄 추가). 처리 순서 = 배열 순서.
- src/game/tycoon/state.ts, (새) — `TycoonState = { version: 1, seq: number, systems: Record<string, unknown> }`, createTycoon, restoreTycoon(raw, systems, ctx)(모르는 시스템 키는 버리지 말고 보존, 없는 키는 create), runMinute/runDay.
- src/game/session.ts, — ① state.tycoon 추가(새 게임은 create) ② 세이브 version 6으로 저장, 불러오기는 1~5 기존대로 + 6. v5 이하는 tycoon 없음 → 빈 그릇(돈·잔액 변화 0) ③ tick의 분 루프 끝(기존 처리 뒤)에 runMinute, 하루 결산(settleShops·advanceDay) 직후 runDay ④ 반환 객체에 `tycoon: { ctx: () => TycoonCtx, state: () => TycoonState, command<T>(systemId, fn: (ctx, s) => T): T }`(command는 실행 뒤 저장 표시). 테스트용으로 createSession(storage, npcSeed, systems = tycoonSystems) 세 번째 인자 허용.
- tests/game/tycoon-registry.test.ts (새)
크기: 큼(≤400줄, 마스터 이유: 세션 연결·세이브 이전·결정론 테스트가 한 번에 필요)
하지 말 것: 기존 게임 규칙·숫자 변경, 기존 테스트 수정, 기존 세이브 형식(1~5) 해석 변경, 새 돈 생성, Math.random 추가, 새 npm 패키지.
통과 기준(테스트):
1. v5 세이브(현재 main으로 만든 세이브 문자열)를 열면 tycoon이 빈 그릇이고 모든 잔액·임대·가게가 그대로.
2. 테스트용 시스템 2개(분마다 roll로 카운터 증가 / 하루마다 settle로 두 주민 사이 1결 왕복)를 넣고: tick(1440×3) 한 번 vs tick(1)×4320 의 tycoon 상태·원장 잔액이 같다. 저장→불러오기 후 이어서 진행해도 같다.
3. 등록부 순서대로 실행된다. validate가 throw하면 기존처럼 손상 세이브 백업 + 새 게임.
4. 총액 보존.
